# Benchmark Methodology

## Measurement Framework

All benchmarks use a custom dependency-free harness (`benchmarks/harness.mts`) built on `process.hrtime.bigint()`.

### Single-Call Operations (`measureOps`)

1. **Warmup**: 2,000 iterations to trigger JIT compilation and NAPI fast-path initialization.
2. **Calibration**: Exponentially growing batch sizes until one batch takes ~5ms (determines per-op cost).
3. **Sampling**: Continues until at least `targetMs` (120ms quick / 300ms full) of measurement elapses.
4. **Percentiles**: Per-batch mean latency sampled; p50/p95/p99 computed from sorted samples.
5. **Reporting**: ops/sec = 1e9 / mean_ns_per_op.

### Bulk Operations (`measureBulk`)

1. **Warmup**: Single call with `min(items, 10_000)`.
2. **GC**: Forced between reps via `global.gc()` (requires `--expose-gc`).
3. **Measurement**: Best-of-N wall-time reps (5 for ≤100K, 3 for 1M, 1 for 10M).
4. **RSS**: `process.memoryUsage.rss()` delta before/after.
5. **Reporting**: IDs/sec = items / best_ns * 1e9.

### Cross-Language Runner (`benchmarks/runner/run.mjs`)

- Detects available toolchains (node/rust/python/go/java).
- Each language's suite runs independently and writes results to `results/YYYY-MM-DD/<lang>.json`.
- Node/Rust/Python emit `BEGIN_RESULTS…END_RESULTS` framed JSON.
- Go output parsed from `go test -bench -benchmem` text.
- Java kept as raw JMH text.
- Report generated by `runner/report.mjs` from the newest day's results.

### Rust Direct (`cargo run --release -p rivid-core --example bench_direct`)

- 5–50M iterations per single operation.
- 100K–10M for bulk operations.
- No NAPI overhead; measures pure Rust core performance.

### PostgreSQL (`benchmarks/db-postgres.mts`)

- Docker container: `postgres:16.4-alpine`, port 54329.
- Tuned config: `shared_buffers=256MB`, `fsync=on`, `synchronous_commit=on`.
- Batch inserts: 10K-row multi-statement VALUES in a single transaction.
- Point lookups: 200 random PK queries per layout.
- Measures: insert ms, rows/sec, `pg_total_relation_size`, index size.

### ORM Layer Separation (`benchmarks/orm/run.mts`)

- **L0**: Pure `rivid.ulid()` generation (ns/op).
- **L1**: Raw `pg` client bulk INSERT (rows/sec).
- **L2**: Drizzle ORM single INSERT (p50/p95 µs).
- Drizzle overhead = L2 p50 − L1 p50.

## Variance Protocol

- 3 independent runs for baseline establishment.
- `spread` = max − min across runs.
- Operations with spread > 20% of mean are flagged as high-variance.
- Bulky operations (≥100K items) have spread < 5%.

## Definitions

- **ns/op**: nanoseconds per operation (lower is better).
- **ops/sec**: operations per second (higher is better).
- **IDs/sec**: identifiers generated per second.
- **p50/p95/p99**: latency percentiles.
- **RSS Δ**: resident set size change in MB.
- **noop baseline**: raw NAPI call overhead (void→void).
